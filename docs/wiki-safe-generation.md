# Wiki 安全生成与 9224 使用说明

仅作用于长期测试栈 9224。生产、latest、原库嵌入绑定不变；邀请制并发改动不在修复中。

## 管理员配置一次

1. “用户设置 → 模型提供商”：添加服务实例、验证聊天与嵌入模型；“设置默认模型”设置工作区默认值。凭据只由 OWNER/ADMIN 管理，普通成员只得到可执行模型元数据。
2. “智能体”管理页配置 Wiki 编译模板组。这里同时管理聊天 Agent、数据管道和模板，跳转不意味着需要创建聊天助手。已有模板组直接打开编辑；普通成员可以查看/选择，不能保存或删除工作区模板。
3. 数据管道的 Compiler 显式选择聊天模型与 Wiki 模板组。工作区默认聊天模型不能补齐空的 Compiler 模型。
4. 新文件解析管道还须具备读取、解析和输出 chunk 的完整链路。小样本实测 File → Parser → Compiler → Tokenizer；文本 Parser 类别为 `text&code`。只含 Compiler 的旧画布可提供已解析文件的 Wiki 配置，不能据此宣称新文件解析链路完整。
5. 知识库“配置 → 解析”选择管道，文件也须绑定。改变文件解析管道会要求重新解析，不是无成本更新。

## 普通用户

知识库创建者：文件列表“上传” → 解析 → 等待成功 → “知识成果”检查准备状态 → 首次“生成”，以后文件变化且解析完成后“更新”。已有管道无需重建。只读用户可阅读，联系创建者或管理员生成。

不要用“清空”代替更新。旧版持续可读，新版本完整、来源未变化、版本正文存储成功后才发布。限流/模板失效/中途失败保留旧版并给出提示。主页面重复返回按钮删除，详情返回列表保留。

## 模型优先级（实际代码）

- Wiki MAP：各文件管道第一个有效 Compiler 显式模型。缺失时阻止生成，不用工作区默认聊天模型兜底。
- Wiki REFINE：按文件创建时间升序，第一个有效 Wiki 模板对应文件的 Compiler 模型。多管道可有多个 MAP 模型，页面列出实际解析结果。
- Wiki worker 嵌入：知识库 `tenant_embd_id` → 失效/特定工厂缺凭据时知识库 `embd_id` 引用 → 没有引用时工作区默认嵌入。跨工作区 ID 被拒绝，不能当失效 ID 回退。
- Pipeline Compiler/Tokenizer：绑定知识库时优先其模型 ID，失效 ID 回退其模型引用；无知识库时用工作区默认嵌入。此分支不等同于 Wiki worker 的全部回退规则。
- 解析和 LLMBundle 使用资源所属工作区，未发现上述路径硬编码个人账号、原库 ID、Gemini 或 DeepSeek。测试脚本固定 fixture ID 不属于产品选择。
- 准备状态显示配置及绑定来源，不执行 provider 探活。配置有效不表示配额可用。

## 安全验证

`common/wiki_generation.py` 以真实 ES mapping/settings 创建私有生成索引。模型变化后的清空仅影响私有副本。发布指针与版本记录事务提交后切换，旧物理版本保留。缺配置阻止入队；生成/编辑/清空互斥。

真实 ES/MySQL/MinIO 受控故障：429、模型变化、中途失败、不完整、取消、模板失效、版本存储失败保留旧版；成功才切换。独立工作区管理员显式配置新实例，普通成员通过产品 API 上传、解析文本，真实生成 7 页 Wiki。原库未重新调用 Gemini。
